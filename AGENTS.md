# Сайт турклубу «Глобус» — інструкція для ШІ-агента

Прототип нового сайту турклубу КПІ «Глобус» (старий сайт — https://www.tkg.org.ua).
Код пише ШІ, супервізор — Михайло (не розробник): пояснюй коротко й простою мовою.

## Контекст — у `../planning/`

Цей репозиторій лежить у робочому просторі поруч із `planning/` (памʼять проєкту, окремо від коду).
Перед роботою прочитай:

- `../AGENTS.md` — карта робочого простору;
- `../planning/CONTEXT.md` — поточний стан;
- `../planning/specs/0001-mvp-prototype.md` — специфікація;
- `../planning/decisions/` — ADR (рішення); не вигадуй рішень поза ними — питай супервізора;
- свій тікет у `../planning/tickets/`.

Терміни (МКК, к.с., н/к…) — з `../planning/glossary.md`.
Якщо `../planning/` немає (репо склоновано окремо) — попроси супервізора про робочий простір.

## Стек

Astro (статична генерація) + Tailwind CSS 4. Хостинг — Cloudflare Pages (проєкт `tk-globus`):
`main` → https://tk-globus.pages.dev, кожна гілка/PR → превʼю-адреса. Node — версія з `.nvmrc`.

## Команди

| Команда | Що робить |
|---|---|
| `npm install` | встановити залежності |
| `npm run dev` | локальний сервер розробки, http://localhost:4321 |
| `npm run build` | зібрати сайт у `dist/` (невалідні дані ламають збірку) |
| `npm run preview` | показати зібраний `dist/` |
| `npm run lint:tokens` | лінт «тільки токени» |
| `npm run check:links` | внутрішні посилання в `dist/` (після build) |
| `npm run test:scripts` | тести скриптів (`node --test`) |
| `npm run test:smoke` | смоук-тести Playwright проти зібраного сайту (після build) |
| `npm run check` | усе разом — те саме, що CI. Запускай перед PR |

Перший запуск смоук-тестів: `npx playwright install chromium`.

## Компоненти

Усі на `/styleguide` із прикладами — дивись там, перш ніж робити новий.

| Компонент | Для чого |
|---|---|
| `Section` | смуга сторінки з колонкою, заголовком і вступом; `tone`: paper / surface / brand; слот `action` |
| `Hero` | перший екран: велике фото, заголовок, вступ, кнопки |
| `PageHeader` | шапка звичайної сторінки: хлібні крихти, h1, вступ; слот під вступом |
| `Breadcrumbs` | хлібні крихти («Головна» додається сама) |
| `Button` | кнопка/посилання: `variant` primary / secondary, `size` md / lg, `href: null` — неактивна |
| `Card` | базова картка (фото, слоти `meta` і `footer`); основа карток новини, події, звіту |
| `CardGrid` | сітка карток: 1 → 2 → `columns` колонки |
| `Activities` | блок «напрями діяльності» |
| `EmptyState` | порожній стан («нічого не знайдено», 404) |
| `Tag` | мітка (район, вид, к.с.) |
| `Cluster` | ряд кнопок чи міток із переносом |
| `Prose` | довгий текст (тіло новини чи сторінки) |
| `Icon` | лінійна іконка; нова — шлях у `lib/icons.ts` |
| `Container` | контентна колонка (будівельний блок інших компонентів) |
| `SiteHeader`, `NavMenu`, `SiteFooter`, `PrototypeBanner` | шапка з меню (на телефоні згортається), підвал, банер |

## Правила

1. **Тільки токени** (ADR 0003). Кольори, шрифти, відступи — лише утиліти з токенів теми
   (`bg-brand`, `text-ink`, `p-4`, `max-w-page`). Заборонено поза `src/styles/`: hex/rgb-кольори,
   довільні значення Tailwind (`mt-[13px]`), стандартна палітра Tailwind (`bg-red-500`, `text-white`),
   `style="…"`, блоки `<style>`. Потрібне нове значення — додай токен у `theme.css`.
   Стандартні розміри тексту, радіуси, тіні й ширини Tailwind вимкнено: `rounded-xl` чи `max-w-2xl`
   мовчки нічого не дадуть — бери лише токени, показані на `/styleguide`.
2. **Сторінки — лише з компонентів**, без власних стилів (`class` на сторінці — ознака, що бракує
   компонента). Кожна сторінка обгортається `BaseLayout`, вміст — секціями (`Section`, `Hero`, `PageHeader`).
   Новий компонент → зразок на `/styleguide` (смоук-тест перевіряє, що зразок є).
3. **Дані — через схеми.** Налаштування — у `settings.json`; контент (тікети 05+) — content collections
   зі строгими схемами, сумісними з Keystatic. Тексти каналів, адреси тощо не зашивай у компоненти.
4. **Прототип:** на кожній сторінці `noindex` і банер; `robots.txt` забороняє індексацію. Не прибирати.
5. **Нові маршрути** додавай у список `routes` у `tests/smoke/routes.ts` (базові перевірки й мобільна
   ширина), а пункт меню вмикай у `src/lib/nav.ts` (замість `null` — адреса).
6. **Мова** інтерфейсу, коментарів і документації — українська.

## Процес (ADR 0006)

1. Тікет → гілка → код → `npm run check` локально → PR.
2. CI зелений + превʼю Cloudflare → статус тікета `in-review`, посилання на PR і превʼю — Михайлу.
   **Тут виконавець зупиняється і не мерджить.** Гілку `main` захищено: мердж лише через PR із зеленим CI.
3. Незалежний верифікатор (нова сесія, `../planning/prompts/verify-ticket.md`) перевіряє пункти тікета
   і дописує звіт у файл тікета.
4. Михайло проходить «Як перевірити (Михайло)» і пише виконавцю «мерджи».
5. Виконавець мерджить, позначає пункти тікета, ставить статус `done`, оновлює `../planning/CONTEXT.md`.

Нове рішення — новий ADR у `../planning/decisions/` (після «ок» Михайла).
