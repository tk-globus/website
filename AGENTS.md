# Сайт турклубу «Глобус» — інструкція для ШІ-агента

Прототип нового сайту турклубу КПІ «Глобус» (старий сайт — https://www.tkg.org.ua).
Код пише ШІ, супервізор — Михайло (не розробник): пояснюй коротко й простою мовою.

## Контекст — у `../planning/`

Цей репозиторій лежить у робочому просторі поруч із `planning/` (памʼять проєкту, окремо від коду).
Перед роботою прочитай:

- `../AGENTS.md` — карта робочого простору;
- `../planning/CONTEXT.md` — поточний стан;
- `../planning/specs/0001-mvp-prototype.md` — специфікація;
- `../planning/decisions/` — ADR (рішення); не вигадуй рішень поза ними — питай супервізора;
- свій тікет у `../planning/tickets/`.

Терміни (МКК, к.с., н/к…) — з `../planning/glossary.md`.
Якщо `../planning/` немає (репо склоновано окремо) — попроси супервізора про робочий простір.

## Стек

Astro (статична генерація) + Tailwind CSS 4. Хостинг — Cloudflare Pages (проєкт `tk-globus`):
`main` → https://tk-globus.pages.dev, кожна гілка/PR → превʼю-адреса. Node — версія з `.nvmrc`.

## Команди

| Команда | Що робить |
|---|---|
| `npm install` | встановити залежності |
| `npm run dev` | локальний сервер розробки, http://localhost:4321 |
| `npm run build` | зібрати сайт у `dist/` (невалідні дані ламають збірку) |
| `npm run preview` | показати зібраний `dist/` |
| `npm run lint:tokens` | лінт «тільки токени» |
| `npm run check:links` | внутрішні посилання в `dist/` (після build) |
| `npm run test:scripts` | тести скриптів (`node --test`) |
| `npm run test:smoke` | смоук-тести Playwright проти зібраного сайту (після build) |
| `npm run check` | усе разом — те саме, що CI. Запускай перед PR |
| `npm run import -- news` | імпорт новин зі старого сайту (див. «Імпортер»); не частина збірки й CI |

Перший запуск смоук-тестів: `npx playwright install chromium`.

## Компоненти

Усі на `/styleguide` із прикладами — дивись там, перш ніж робити новий.
Корінь кожного компонента позначено `data-component="Назва"` (як файл); смоук-тест шукає цю позначку
на зібраній `/styleguide`, тож новий компонент без позначки чи без живого зразка ламає тести.

| Компонент | Для чого |
|---|---|
| `Section` | смуга сторінки з колонкою, заголовком і вступом; `tone`: paper / surface / brand; слот `action` |
| `Hero` | перший екран: велике фото, заголовок, вступ, кнопки |
| `PageHeader` | шапка звичайної сторінки: хлібні крихти, h1, вступ; слот під вступом |
| `Breadcrumbs` | хлібні крихти («Головна» додається сама) |
| `Button` | кнопка/посилання: `variant` primary / secondary, `size` md / lg, `href: null` — неактивна |
| `Card` | базова картка (фото, слоти `meta` і `footer`); основа карток новини, події, звіту |
| `CardGrid` | сітка карток: 1 → 2 → `columns` колонки |
| `Activities` | блок «напрями діяльності» |
| `EmptyState` | порожній стан («нічого не знайдено», 404) |
| `Tag` | мітка (район, вид, к.с.) |
| `Cluster` | ряд кнопок чи міток із переносом |
| `Prose` | довгий текст (тіло новини чи сторінки) |
| `Icon` | лінійна іконка; нова — шлях у `lib/icons.ts` |
| `Container` | контентна колонка (будівельний блок інших компонентів) |
| `SiteHeader`, `NavMenu`, `SiteFooter`, `PrototypeBanner` | шапка з меню (на телефоні згортається), підвал, банер |

## Імпортер

Окремий скрипт `scripts/import/` (ADR 0004): читає публічні сторінки tkg.org.ua і пише Markdown-файли
контенту з фото. Не частина збірки: запускається руками, результат комітиться.

```
npm run import -- news                 # вибірка для прототипу (новини 2023–2026 з аудиту)
npm run import -- news --scope all     # усі новини зі сторінок архіву (терміни 2191, 2180 — роки 2021–2026)
npm run import -- news --limit 3       # лише перші 3
npm run import -- news --refresh       # завантажити заново, а не з кешу
```

- **Ввічливий режим:** кеш сторінок і фото в `.cache/old-site/` (у `.gitignore`), пауза 1,5–2 с між
  запитами в мережу. Повторний запуск з кешем не робить жодного запиту.
- **Без дублікатів:** файл шукається за `legacyUrl` у вже імпортованих записах — той самий оригінал
  завжди пише в той самий файл, навіть якщо заголовок змінився. Новий файл — slug із заголовка
  (транслітерація), при збігу — з номером вузла (`…-37931`). Незмінний запис файл не чіпає.
- **Ручні правки** імпортованого файлу перезапише наступний імпорт цього запису.
- **Фото:** оригінал (без `styles/…/public/`) → `src/assets/<тип>/<slug>/`. Перше фото новини стає
  обкладинкою (`cover`) і з тексту прибирається. Посилання на старий сайт стають абсолютними.
- **Звіт:** `+ нове`, `~ оновлено`, `= без змін`, `!` попередження (немає обкладинки…), `✗` помилка.
  Помилка одного запису не зупиняє інші, але код виходу — 1.

Будова: `index.mjs` (командний рядок) → `core.mjs` (адреси, slug, фото, запис файлів — спільне для всіх
типів) → `types/<тип>.mjs` (парсер одного типу) з помічниками `html.mjs` (дати, фото-оригінали,
списки-тизери, HTML → Markdown), `fetcher.mjs` (кеш і паузи), `slug.mjs`. Вибірка — `samples/news-events.json`
(копія `planning/research/data/news-events-sample.json`).

**Новий тип контенту** (подія, звіт, сторінка):
1. Схема `src/lib/schemas/<тип>.ts` (лише `astro/zod`, дати — `isoDate()`), колекція в `src/content.config.ts`
   (обгорнута в `withRawDates`, якщо є дати).
2. Парсер `scripts/import/types/<тип>.mjs` з інтерфейсом, описаним у `types/index.mjs`
   (`parse` повертає поля схеми, обкладинку й HTML тіла; фото й Markdown робить ядро), і рядок у `types`.
3. Тест на фікстурах у `tests/scripts/` за зразком `import-news.test.mjs`: результат проходить схему,
   поля й legacy URL правильні, мережі немає (підміна завантажувача).
4. Запуск `npm run import -- <тип>`, перевірка `npm run check`, коміт файлів контенту й фото.

## Правила

1. **Тільки токени** (ADR 0003). Кольори, шрифти, відступи — лише утиліти з токенів теми
   (`bg-brand`, `text-ink`, `p-4`, `max-w-page`, `font-bold`, `border-line/soft`, `opacity-disabled`).
   Заборонено поза `src/styles/` (ловить `npm run lint:tokens`): hex/rgb-кольори, довільні значення
   Tailwind (`mt-[13px]`), стандартна палітра Tailwind (`bg-red-500`, `text-white`), числа в обхід теми —
   прозорість (`opacity-60`, `border-line/40`), висота рядка (`leading-6`, `text-sm/6`), товщина ліній
   (`border-2`, `ring-2`, `underline-offset-4`), тривалість (`duration-300`) — а також `style="…"` і
   блоки `<style>`. Потрібне нове значення — додай іменований токен у `theme.css` (і приклад на `/styleguide`:
   тест перевіряє, що кожен токен там показано).
   Стандартні значення Tailwind, що мають бути в темі (накреслення, висота рядка, радіуси, тіні, ширини,
   точки переходу…), вимкнено: `rounded-xl`, `font-light` чи `xl:` мовчки нічого не дадуть — бери лише
   токени з `/styleguide`. Розкладка — не тема: кількість колонок (`grid-cols-3`), пропорції фото
   (`aspect-3/2`), шари (`z-30`), обрізання тексту (`line-clamp-3`) пишуться числами в компонентах.
2. **Сторінки — лише з компонентів**, без власних стилів (`class` на сторінці — ознака, що бракує
   компонента). Кожна сторінка обгортається `BaseLayout`, вміст — секціями (`Section`, `Hero`, `PageHeader`).
   Новий компонент → `data-component` на корені і зразок на `/styleguide` (смоук-тест перевіряє обидва).
   Заголовки на сторінці — один h1, далі без пропусків рівня (смоук-тест); компоненти із заголовком
   мають проп `headingLevel`.
3. **Дані — через схеми.** Налаштування — у `settings.json`; контент (тікети 05+) — content collections
   зі строгими схемами, сумісними з Keystatic. Тексти каналів, адреси тощо не зашивай у компоненти.
4. **Прототип:** на кожній сторінці `noindex` і банер; `robots.txt` забороняє індексацію. Не прибирати.
5. **Нові маршрути** додавай у список `routes` у `tests/smoke/routes.ts` (базові перевірки, мобільна
   ширина, порядок заголовків), а пункт меню вмикай у `src/lib/nav.ts` (замість `null` — адреса).
6. **Мова** інтерфейсу, коментарів і документації — українська.

## Процес (ADR 0006)

1. Тікет → гілка → код → `npm run check` локально → PR.
2. CI зелений + превʼю Cloudflare → статус тікета `in-review`, посилання на PR і превʼю — Михайлу.
   **Тут виконавець зупиняється і не мерджить.** Гілку `main` захищено: мердж лише через PR із зеленим CI.
3. Незалежний верифікатор (нова сесія, `../planning/prompts/verify-ticket.md`) перевіряє пункти тікета
   і дописує звіт у файл тікета.
4. Михайло проходить «Як перевірити (Михайло)» і пише виконавцю «мерджи».
5. Виконавець мерджить, позначає пункти тікета, ставить статус `done`, оновлює `../planning/CONTEXT.md`.

Нове рішення — новий ADR у `../planning/decisions/` (після «ок» Михайла).
